## Objective
Inventory every frontend route, component and state pattern at the baseline, and classify
each against the V2 UX requirements — progressive disclosure, office speed, and field
usability.

## Product context
The baseline contains roughly 40 page routes including a `(mobile)` technician application,
built against a retired product boundary and without progressive disclosure primitives. V2
requires role-based interfaces, feature modules, contextual actions, command/search, saved
workspaces and permission-based navigation. Some existing screens are reusable; some encode
a navigation model that V2 explicitly rejects.

## User story
As a designer planning the V2 design system, I need to know which existing screens can be
carried forward and which encode patterns we are deliberately abandoning, so Sprint 1 scopes
the design system against reality.

## Scope
All routes under `apps/web/app/`, shared components, layout shells, state management, API
client layer, and styling approach.

## Deliverables
1. `docs/audit/FRONTEND-INVENTORY.md`: per route — path, route group, purpose, server or
   client component, data fetching approach, backing API endpoints, auth requirement,
   responsive status, classification, rationale.
2. Component inventory: shared components, usage count, design token adherence, accessibility status.
3. Navigation model assessment: current navigation structure evaluated against the V2
   progressive disclosure requirement, with an explicit statement of what must change.
4. Design system gap analysis: what exists today versus what Sprint 1 must produce — tokens,
   primitives, patterns, density options, role-based shells.
5. Office UX assessment against `AGENTS.md` §3: which speed affordances exist today
   (keyboard navigation, bulk operations, inline editing, saved views, global search,
   persistent filters) and which are absent.
6. Field UX assessment against `AGENTS.md` §3: touch target sizes, navigation depth per core
   action, offline behaviour, duplicate entry points.
7. Accessibility baseline: keyboard support, focus management, contrast, form semantics,
   measured rather than assumed.

## Classification rubric
KEEP / REFACTOR / REPLACE / REMOVE with written rationale. A screen that works but encodes a
rejected navigation model is REPLACE, not KEEP.

## Acceptance criteria
- [ ] All ~40 routes inventoried and classified with rationale
- [ ] Shared components inventoried with usage counts
- [ ] Navigation model assessment complete with explicit V2 gap statement
- [ ] Office UX affordance checklist completed as measured fact
- [ ] Field UX assessment includes measured navigation depth for each core technician action
- [ ] Accessibility baseline measured, not estimated
- [ ] Design system gap analysis feeds directly into Sprint 1 scope
- [ ] Each REPLACE names its target sprint
- [ ] No frontend behaviour changed

## Required tests
None added. Existing frontend tests run and their results recorded for FSM-0007.

## Impact
**API:** none. **Database:** none. **Frontend:** inventory only, no behaviour change.
**Mobile:** the `(mobile)` route group is assessed in full as it becomes the Sprint 6 starting
point. **Integration:** none.

## Security considerations
Flag any frontend component containing business logic, performing authorisation decisions
client-side, or embedding credentials. Client-side authorisation is a P0 finding for FSM-0009.

## Tenant isolation considerations
Flag any component that receives or trusts a tenant identifier from client-side state rather
than from the authenticated session.

## Observability requirements
Record current client-side error tracking and performance instrumentation; gaps feed Sprint 1.

## Migration requirements
None.

## Rollback considerations
Documentation only.

## Non-goals
Not redesigning. Not building design system tokens. Not fixing accessibility. Not
implementing progressive disclosure. Findings and classification only.

## Required review
FE-01 implements · FE-02 peer reviews · DES-01 reviews the navigation model assessment and
design system gap analysis · DES-02 reviews the field UX assessment.

## Required QA
QA-01 spot-checks 20% of route classifications against source and verifies the accessibility
baseline is reproducible.

## Completion procedure
Merge → feed into FSM-0012 and Sprint 1 design system scope → update `PROJECT_STATE.md` §5.
