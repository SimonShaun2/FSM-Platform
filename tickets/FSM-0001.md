## Objective
Reconcile the local working tree with `origin/main` and establish a verified, tagged,
protected baseline commit that the entire Sprint 0 audit is performed against.

## Product context
`origin/main` was last pushed 2026-05-02. Local builds were never configured to auto-push.
`docs/planning/PHASE3-REMAINING-TICKETS.md` names "TICKET-034 APPROVED" as a prerequisite,
yet no TICKET-034 commit exists on `main` — proving at least one approved unit of work
exists only on the founder's machine. Auditing a stale remote produces a worthless baseline,
so every other Sprint 0 ticket waits on this one. See `PROJECT_STATE.md` BD-002 and BD-003.

## User story
As the Technical Lead, I need a single verified commit representing all work ever completed,
so that classification decisions are made against reality rather than a partial snapshot.

## Scope
Enumerate local commits absent from origin. Review each for secrets, credentials and
generated artifacts before pushing. Push reconciled history preserving authorship and dates.
Retroactively tag documented milestones. Establish branch protection. Record the baseline
commit SHA in `PROJECT_STATE.md`.

## Deliverables
1. All local work present on `origin/main`, history preserved, no force-push over existing history.
2. Annotated tags `v1.0.0` and `v3.0.0` applied to their correct historical commits, or a
   written record in the audit explaining why a defensible commit could not be identified.
3. `v2.0.0-baseline` annotated tag on the reconciled HEAD, marking the Sprint 0 audit target.
4. Branch protection on `main`: no direct pushes, PR required, CI required once FSM-0010 lands.
5. `.gitignore` verified against the reconciled tree; generated artifacts removed from tracking.
6. `docs/audit/REPOSITORY-RECONCILIATION.md` — commits pushed, tags applied, artifacts removed, residual risks.
7. `PROJECT_STATE.md` §2 updated with the verified baseline SHA and corrected counts.

## Acceptance criteria
- [ ] `git log origin/main..HEAD` on the founder's machine returns empty
- [ ] `git ls-remote --tags origin` lists `v1.0.0`, `v2.0.0`, `v3.0.0`, `v2.0.0-baseline`, or the audit documents each exception
- [ ] No secret, credential, `.env` file or key material exists anywhere in the pushed tree
- [ ] Secret scanning run across full history; findings documented and remediated
- [ ] `node_modules`, build output and generated sources are untracked
- [ ] Branch protection active on `main`
- [ ] Baseline SHA recorded in `PROJECT_STATE.md`
- [ ] `pnpm install && pnpm build` succeeds from a clean clone of the baseline
- [ ] Every subsequent Sprint 0 ticket references the baseline SHA

## Required tests
Clean-clone verification: fresh clone of `v2.0.0-baseline`, `pnpm install`, `pnpm build`,
`pnpm test`. Results recorded verbatim — a failing build is a finding to document under
FSM-0007, not a reason to fix code in this ticket.

## Impact
**API:** none. **Database:** none. **Frontend:** none. **Mobile:** none.
**Integration:** none — but any credential found in history must be treated as compromised
and rotation scheduled under FSM-0009.

## Security considerations
History rewriting is out of scope unless a secret is found. If one is: rotate the credential
first, document under FSM-0009, and escalate history rewriting to TL-01 as an explicit
authorised decision. Do not silently rewrite shared history.

## Tenant isolation considerations
None directly. If any real customer data exists in seed files or fixtures, flag it for
FSM-0009.

## Observability requirements
None. Record the reconciliation event in `CHANGELOG.md`.

## Migration requirements
None.

## Rollback considerations
Capture the pre-reconciliation origin SHA in the reconciliation document before any push, so
the prior remote state is recoverable.

## Non-goals
Not fixing failing tests. Not fixing the schema drift (FSM-0004). Not rewriting governance
(FSM-0002). Not classifying code (FSM-0003 onward). This ticket establishes the baseline and
nothing else.

## Required review
DO-01 implements · TL-01 reviews · founder authorisation required before first push to `main`.

## Required QA
QA-03 verifies the clean-clone build and confirms the baseline is reproducible.

## Completion procedure
Merge → update `PROJECT_STATE.md` §2 and §5 → update `CHANGELOG.md` → unblock FSM-0002
through FSM-0011 → notify all owners of the baseline SHA.
