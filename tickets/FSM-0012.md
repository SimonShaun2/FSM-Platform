## Objective
Consolidate every Sprint 0 finding into a single authoritative audit, issue the final
KEEP / REFACTOR / REPLACE / REMOVE classification for every component, and produce the
migration plan that governs Sprint 1 onward.

**This is the Sprint 0 exit gate. No V2 feature work begins until this ticket merges.**

## Product context
Master directive §50 requires the audit to become the restart baseline. Eight separate
inventories now exist. They must be reconciled into one decision record, because
contradictory audits are as bad as no audit. Where inventories disagree, this ticket resolves
the disagreement.

## User story
As any team member starting Sprint 1, I need one document that tells me what survives, what
changes, what gets rebuilt and in which sprint, so I never have to reconcile eight separate
reports myself.

## Scope
All Sprint 0 audit outputs. No new investigation except where inventories conflict.

## Deliverables
1. **`EXISTING_CODE_AUDIT.md`** — the consolidated audit at repository root. Executive
   summary, methodology, component classification table, risk register, and the rebaseline
   decision with reasoning.
2. **Master classification table** — every meaningful component: name, type, owning domain,
   classification, rationale, owning sprint, size estimate. Nothing unclassified.
3. **`MIGRATION_PLAN.md`** — how the codebase moves from baseline to V2 target: sequence,
   breaking changes, data migration, rollback, dependencies between migration steps.
4. **Rebaseline decision** — a plain statement of whether V2 extends the existing codebase or
   substantially rebuilds it, per domain, with reasoning drawn from FSM-0011.
5. **Consolidated risk register** — every risk from every audit, deduplicated, ranked by
   impact × likelihood, each with an owning sprint and mitigation.
6. **Sprint 1 scope confirmation** — the audit will have changed Sprint 1's shape. State how.
7. **Roadmap adjustment** — any sprint whose scope or sequence must change based on findings,
   with `SPRINT_ROADMAP.md` updated accordingly.
8. **Conflict resolution record** — where two inventories disagreed, which one was correct and why.

## Acceptance criteria
- [ ] Every component in every inventory appears in the master classification table
- [ ] No component classified without a written rationale
- [ ] Every REPLACE and REFACTOR item assigned an owning sprint and size estimate
- [ ] Rebaseline decision stated unambiguously per domain
- [ ] `MIGRATION_PLAN.md` sequences every change with dependencies
- [ ] Consolidated risk register deduplicated and ranked
- [ ] Every P0 security finding from FSM-0009 has an owning sprint and mitigation
- [ ] Sprint 1 scope confirmed or revised in writing
- [ ] `SPRINT_ROADMAP.md` updated where findings require it
- [ ] Every inventory conflict resolved and recorded
- [ ] `PROJECT_STATE.md` fully updated — baseline defects BD-001 to BD-006 resolved or carried forward with owners

## Required tests
None. Verification is that every input inventory is fully represented.

## Impact
**API / Database / Frontend / Mobile / Integration:** none directly. This ticket determines
the impact of every subsequent sprint.

## Security considerations
Every P0 and P1 finding from FSM-0009 must be represented with an owning sprint. A security
finding that reaches this document without an owner is an incomplete deliverable.

## Tenant isolation considerations
The tenant model decision from FSM-0011 is carried into the rebaseline decision and the
migration plan. If a restructure is required, Sprint 2 scope changes materially and that must
be stated here.

## Observability requirements
Observability gaps from FSM-0003, FSM-0005, FSM-0006 and FSM-0010 consolidated into Sprint 1 scope.

## Migration requirements
This ticket produces `MIGRATION_PLAN.md`.

## Rollback considerations
Documentation only. The baseline tag from FSM-0001 remains the recovery point for the entire
restart.

## Non-goals
Not implementing anything. Not new investigation beyond conflict resolution. Not authoring
the Sprint 1 specification set.

## Required review

## Required QA

Sprint 1 begins immediately without founder approval** per `TEAM.md` §6.
